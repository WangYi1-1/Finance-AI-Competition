# GitHub 同步与本地运行

当前方案是 **GitHub 同步源码，每位组员在自己的电脑运行**，尚未部署云端网页。仓库保持公开，只发布源码、公开财报和已核验的展示成果；API 项留空，各人自己在本地配置 `.env`。取消整个应用每日 10 次分析的限制。每轮模型请求上限仍是 12 次，失败重试也计入，以限制单轮重复调用。

目标仓库：<https://github.com/WangYi1-1/Finance-AI-Competition>。以后更新只需管理员推送一次，组员拉取最新代码；不用反复发压缩包。

## 组员第一次安装

先安装 Git for Windows 和 64 位 Python 3.13。锁定依赖至少需要 Python 3.12，推荐用已测试的 3.13。在准备保存项目的位置打开终端：

```powershell
git clone https://github.com/WangYi1-1/Finance-AI-Competition.git
cd Finance-AI-Competition
```

进入下载的项目文件夹，双击 **首次安装.cmd**。安装完成后双击 **启动财报分析.cmd**，浏览器打开本机 `http://localhost:8501`。先看已有六份公开财报或伊利两份年报的展示成果，这一步不需要 API、不产生模型调用。

需要测试新财报时，在项目文件夹把 `.env.example` 复制成 `.env`，填入自己的 DeepSeek 官方 API 密钥。示例 API 项是空白，不提供任何人的密钥。不要把 `.env` 发群里、上传 GitHub 或提交到 Git：

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

编辑本地 `.env` 后保存，再运行真实分析。每个人的 API 扣费、上传材料和新结果都属于自己本机的运行；只有提取所需的报告片段会发送给自己配置的 DeepSeek 接口。初次安装细节见 [组员测试说明](../组员测试说明.md)。

## 组员以后更新

先关闭正在运行的财报分析窗口，双击 **更新到最新版.cmd**。也可以在项目文件夹打开终端：

```powershell
git pull --ff-only
```

然后重新双击 **启动财报分析.cmd**。若依赖发生变化，再运行一次 **首次安装.cmd**。`.env` 不受 Git 跟踪，拉取源码不会覆盖已填写的个人密钥；`.venv` 和自己的上传、输出目录也不会提交到 GitHub。

如果提示本地文件被修改、分支不同或无法直接快进，先保留修改并发回提示信息核对，不要用强制覆盖命令。组员不要运行 **发布GitHub更新.cmd**；这个入口供维护项目的人发布新版。

## 管理员发布新版

开发项目仍在原目录。双击 **发布GitHub更新.cmd**，程序依次完成：

1. 从明确白名单生成 `deploy/releases/时间_编号/`，不覆盖上次副本。
2. 核对源码、8 份公开 PDF、两组最新封存成果及原始日志、人工核对参考文件。
3. 在固定本地仓库 `deploy/github` 中，对照上次 `cloud_snapshot.json` 检查所有文件哈希和 Git 状态；若本地被别人改动、新增文件或远端 `main` 不一致，则停止。
4. 把已检查的变化同步到固定仓库，正常提交、推送到目标仓库的 `main`，从不强制推送。

固定仓库第一次发布只接受空远端，避免把其他已有项目覆盖掉。此后保留 `deploy/github` 目录，它是连续更新和对照哈希的依据。GitHub 认证由 Git for Windows 的凭据管理完成，发布程序不读取或显示账户 token。默认提交署名为已核实的用户名 `WangYi1-1` 及公开 noreply 邮箱 `WangYi1-1@users.noreply.github.com`，不读取本机个人 Git 身份。

想先复查，可以按阶段运行：

```powershell
# 只准备副本，不接触 GitHub
.\.venv\Scripts\python.exe scripts/publish_cloud_update.py --prepare-only

# 检查副本、本地状态和远端提交，不修改固定仓库、不推送
.\.venv\Scripts\python.exe scripts/publish_cloud_update.py --release "deploy/releases/本次目录名" --dry-run

# 确认这份副本后正常发布
.\.venv\Scripts\python.exe scripts/publish_cloud_update.py --release "deploy/releases/本次目录名"
```

也支持 `--no-push`：同步并生成本地提交后停下，便于人工检查；审核完成后在 `deploy/github` 正常执行 `git push --set-upstream origin main`。没有推送的本地提交会使下次自动发布停止，避免把这种状态误当成已经发布。

## 发布内容与核验

发布副本包括完整应用核心模块、提示词、样式、依赖、测试、运行及验证工具，以及当前最新两组成果和对应公开原文。伊利核对工具需要的两份人工参考文件明确加入清单；其他旧运行、临时上传、真实 `.env`、`.venv`、`secrets.toml` 和开发临时文件排除。

`cloud_snapshot.json` 记录文件大小、SHA-256 和当前展示指针。入选文本及 Excel 内容会扫描疑似 token；配置示例中的 API 和访问码必须为空。原始成果、日志和来源 PDF 保留字节级哈希，`.gitattributes` 禁止 Git 自动转换换行，防止 Windows 与其他系统之间改变封存文件。

核验一份发布副本：

```powershell
.\.venv\Scripts\python.exe scripts/prepare_cloud_release.py --verify "deploy/releases/本次目录名"
```

GitHub 普通仓库拒绝超过 100 MiB 的单文件；浏览器上传单文件限 25 MiB。发布准备会检查普通仓库上限。[GitHub 文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

界面更新不会自动重新分析展示财报。需要更新展示数据时，先在开发目录核验、刷新两个最新指针，再发布。组员自己的分析输出保留在本地，不会自动成为团队公共展示结果。

## 保留的云端兼容代码

`cloud_app.py` 和空白 `.streamlit/secrets.example.toml` 只是可选源码，本次不部署、不登录托管平台，也不配置云端 API。将来如需要仅展示已有成果的公共网页，可以另行启用；实时模型分析仍按各组员本地、各自 API 的当前方案运行。
